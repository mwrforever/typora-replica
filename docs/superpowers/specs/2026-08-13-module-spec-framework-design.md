## 1. 背景与目标

全量功能调研 spec 已定稿（93 个功能点、6 项校准全部确认）。按既定流程，下一步是把它拆分为 12 份模块 spec，逐模块实现。

本设计文档固定「拆分体系」的框架决策：

1. 模块 spec 的统一模板（验收标准驱动）
2. 12 模块的产出顺序与依赖标注方式
3. 每份模块 spec 的撰写流程（调研 → spec → 用户把关）
4. 验收标准的形式约定

| --- | ------------ | -------------------------------------------------------------------------- |


## 4. 模块 spec 统一模板（9 节）

每份 `NN-<模块名>.md` 固定以下结构：

| 节               | 内容                                                                   | 来源            |
| ---------------- | ---------------------------------------------------------------------- | --------------- |
| 0 元信息         | 模块编号/名称/依赖模块/对应全量 spec 功能点编号/状态                   | —               |
| 1 模块定位与边界 | 做什么、**不做什么**（引用全量 spec 第 9 节裁剪结论）                  | 全量 spec       |
| 2 功能点细化     | 每点：行为规范细化 + 触发方式 + 边界条件 + **验收标准**                | 调研文档        |
| 3 非功能要求     | 性能/编码/无障碍等横切项在本模块的落点                                 | 全量 spec C1-C5 |
| 4 测试策略       | 核心功能 100% 单测、非核心 ≥80%、E2E 场景清单                          | AGENTS.md 六    |
| 5 依赖与接口     | 上游依赖、本模块对外暴露的接口（编辑器实例/命令/事件）、前端↔Rust 边界 | 设计            |
| 6 实现阶段划分   | Phase 1..n（每 phase 一批可独立验证的功能点），一个模块一个 PR         | —               |
| 7 验收标准汇总   | 全模块验收清单（checklist，CI 可核对）                                 | 第 2 节汇总     |
| 8 调研引用       | 指向 research/ 文档 + clean-room 合规声明                              | —               |

## 6. 验收标准形式约定

- **编辑行为类**（如段落换行、标题转换）→ Given/When/Then，可直译成 Vitest 用例
- **快捷键/UI 开关类**（如 Ctrl+1~6、菜单项存在性）→ 勾选清单，可直译成 E2E 场景
- 每个功能点 **必须至少 3 条验收标准**（正常/边界/异常），对应 AGENTS.md 6.5 三类场景要求
