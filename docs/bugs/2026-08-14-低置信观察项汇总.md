## OBS-1：editorManager.create() 异常路径无兜底清理

- 位置：`src/services/editor-manager.ts:38-53`（提交 e6f33f6）
- 现象：`create()` 中 `document.body.appendChild(root)` 与 `this.crepe = createMarkwellEditor(...)`
  先于 `await this.crepe.create()` 执行；若 `create()` 抛错（如文档解析异常），root div 与半初始化
  crepe 引用残留。下一次 `create()` 的 `destroy()` 可自愈（crepe 存在则销毁、root 移除），
  但错误发生到下次 create 之间实例处于不一致状态，且错误信息中无残留清理动作。
- 置信度：中-低（异常路径，正常流程不可达；Crepe 解析容错性强，少见抛错）。
- 建议：`create()` 增加 try/catch 兜底（catch 内执行 destroy 清理后重抛），02 模块接入文件打开链时落实。

## OBS-2：EditorPage 的 useEditor 工厂闭包捕获 initialDoc，prop 更新不响应

- 位置：`src/components/editor/EditorPage.vue:34-38`（提交 57e3ea6）
- 现象：`createMarkwellEditor(root, props.initialDoc)` 仅在组件挂载时（Milkdown 组件的 onMounted）读取
  initialDoc 一次，无 watch 监听。父组件后续更新 `initialDoc`（如 02 文档管理切换文件）不会刷新编辑器内容，
  需要销毁重建或新增换档逻辑。
- 置信度：低（当前 App.vue 静态传入 `# 欢迎使用 MarkWell`，无实际触发面；属 02 模块接入点提示）。
- 建议：02 模块设计时明确"打开新文档 = 组件重建 or create(newDoc)"两条路径，勿直接更新 prop 期望生效。

## OBS-3：input-rules.spec 使用非法选区位置，触发 ProseMirror 运行时警告

- 位置：`src/features/editor/input-rules.spec.ts:49、66`（提交 bb30c90）
- 现象：`te.setSelection(doc.content.size, ...)` 在空文档（位置 0 无 inline content）与
  `setSelection(0, 0)`（文档级光标）会触发 ProseMirror 内部警告
  `TextSelection endpoint not pointing into a node with inline content (doc)`（stderr 可见）。
  测试仍通过，但 stderr 被污染，会掩盖其他真实错误信号。
- 置信度：低（测试环境噪音，真实编辑器不会产生文档级光标）。
- 建议：改用真实可达的光标位置（如先插入文本再定位），保持 stderr 干净。

## OBS-4：getMarkdown 尾随换行剥离口径与测试助手不一致（当前等价，未来隐患）

- 位置：`src/services/editor-manager.ts:106`（`replace(/\n+$/, "")`，提交 e6f33f6）
  vs `src/test/editor-test-utils.ts:87`（`replace(/\n$/, "")`，提交 a0c8bb5）
- 验证：remark 序列化对尾随空段落会被解析器丢弃（实测 `"# 标题\n\n"` 解析后再序列化为 `"# 标题\n"`，
  恒为单尾换行），故当前两者输出完全一致，**不丢数据**。
- 风险：若 Crepe 升级或序列化行为变化（如保留空段落），`\n+$` 会剥掉文档真实尾随空行（轻微数据丢失）。
- 置信度：低（当前无触发面）。
- 建议：统一口径为 `replace(/\n$/, "")`（只剥序列化器附加的单换行），并加注释说明依据。
