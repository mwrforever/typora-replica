## 一、高置信缺陷（建议尽快修复）

### [ ] FIX-1 硬换行规则缺少"光标在行尾"判定，段中两空格后按 Enter 误转硬换行

| 项       | 内容                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------ |
| 优先级   | **P1（高）**                                                                                     |
| 风险类别 | 运行错误（行为错误，可复现）                                                                     |
| 引入提交 | `bb30c90` feat(editor): 行尾两空格+Enter 硬换行转换规则（E1-3 回退实现）                         |
| 涉及文件 | `src/features/editor/input-rules.ts`（新增，58 行）                                              |
| 相关测试 | `src/features/editor/input-rules.spec.ts`、`src/features/editor/e1-paragraph.spec.ts`（AC-E1-3） |

**问题描述**

`trailingSpacesHardBreakCommand`（E1-3 行尾两空格硬换行规则）只检查**光标前紧邻两字符是否为空格**，
**未检查光标是否位于行尾（光标后无内容）**。导致段落中间"两空格后"按 Enter 被误判为行尾硬换行：
段落不拆分、强制插入 hardBreak 节点，与 Typora 及 E1-3 AC 的"行尾"语义不符。

**代码证据**（`src/features/editor/input-rules.ts:31-45`）

```ts
export function trailingSpacesHardBreakCommand(state: EditorState, dispatch?: Dispatch): boolean {
  const { selection } = state;
  // 仅处理行内文本光标：非文本选区（跨节点选区）不干预
  if (!(selection instanceof TextSelection) || !selection.empty) return false;
  const { $from } = selection;
  // 光标父节点必须是文本块（段落/标题/列表项等）；文档级光标不处理
  if (!$from.parent.isTextblock) return false;
  // 行尾检测：光标前紧邻的两个字符均为空格才转换（CommonMark 硬换行语法）
  const textBefore = $from.parent.textBetween(0, $from.parentOffset);
  if (!textBefore.endsWith("  ")) return false; // ← 仅检查光标前，无"光标后无内容"校验
  if (!dispatch) return true;
  // 在行尾两空格之后插入 hardBreak 节点；光标随插入映射到换行之后
  dispatch(state.tr.insert($from.pos, state.schema.nodes.hardbreak.create()).scrollIntoView());
  return true;
}
```

**复现实验**（真实 Crepe 7.22.1 + jsdom）

```
场景：直插 "ab␣␣cd"，光标置于两空格之后（"c" 前，doc pos 5），按 Enter
[DBG9] 空格中间 hasHB=true childCount=1 序列化="ab  \\\ncd"
→ 命中！段落未拆分（childCount=1），段中插入 hardBreak，序列化出现 "\\\n" 转义

对照组（段尾场景，正确）：e1-paragraph.spec AC-E1-3 精确重现 → hasHB=true、childCount=1、
序列化="行一  \n"，行为正确
```

**影响**

- 用户段中"两个空格"后按 Enter 期望拆段，实际得到段内硬换行（段落不拆）。
- 该 keymap 以 priority 200 消费 Enter（`chainCommands` 降序优先、命中即阻断内置 splitBlock），
  用户无法在光标前两空格为空格时正常拆段。
- 序列化输出 `␣␣\\\n`（remark 对段中 hardBreak 的转义），落盘语法歧义。

**修复建议**

```ts
// 命中前增加行尾校验：光标之后到块尾无任何内容才视为"行尾"
if ($from.parentOffset !== $from.parent.content.size) return false;
```

同步在 `input-rules.spec.ts` 补负例用例：`ab␣␣cd` 光标在两空格后按 Enter →
断言段落拆分（childCount=2）且无 hardBreak 节点。

### [ ] FIX-2 测试基座 makeTestEditor 挂载根元素泄漏（destroy 不 await、不移除 root）

| 项       | 内容                                            |
| -------- | ----------------------------------------------- |
| 优先级   | **P1（高，测试基建，影响所有后续用例可靠性）**  |
| 风险类别 | 资源泄漏（DOM 节点跨用例累积）                  |
| 引入提交 | `a0c8bb5` test(editor): 搭建编辑器测试基座      |
| 涉及文件 | `src/test/editor-test-utils.ts`（新增，101 行） |

**问题描述**

`makeTestEditor` 向 `document.body` 追加挂载根 div（`editor-test-utils.ts:60-61`），
收尾清理 `destroyTestEditors`（`editor-test-utils.ts:41-49`）存在两个缺陷：

1. **不 await `crepe.destroy()`**：`Editor.destroy` 为异步流程，同步返回时内部 DOM 尚未清理；
2. **不移除 root div**：`@milkdown/core` view-clear 销毁时只移除 `.milkdown` 容器
   （`core/lib/index.js:480-483` `container?.remove()`），外部 root div 不在其清理范围——
   产品路径 `editorManager.destroy()` 有 `this.root?.remove()` 补偿（`editor-manager.ts:80`），
   测试基座缺失该补偿。

**代码证据**

```ts
// editor-test-utils.ts:41-49
export function destroyTestEditors(): void {
  for (const crepe of liveEditors.splice(0)) {
    try {
      crepe.destroy(); // ← ① 不 await：异步清理未完成即返回
    } catch {
      // 销毁失败不阻塞用例收尾
    }
  }
  // ← ② 缺失 root.remove()
}
```

**复现实验**

```
[DBG-B2] before=0 afterCreate=13 afterDestroySync=13 afterMicrotask=1 strayRootDivs=1
→ 同步检查 13 个 div 全部残留（异步销毁未执行）；await 50ms 后内部 12 个已清理，
  但 root div 永久残留（strayRootDivs=1），每用一次 makeTestEditor 累积 1 个
```

**影响**

- 测试文件内用例间 DOM 累积，污染依赖 `document.body` 全局查询的精确计数断言
  （`editor-manager.spec.ts:44-48`「连续 create 两次无重叠」目前因执行顺序侥幸安全，属脆弱断言）。
- 与产品路径行为不一致，掩盖"销毁是否干净"的验证能力。

**修复建议**

```ts
// makeTestEditor 登记 { crepe, root }，destroyTestEditors 改为：
export async function destroyTestEditors(): Promise<void> {
  for (const entry of liveEditors.splice(0)) {
    try {
      await entry.crepe.destroy(); // 等待异步销毁完成
      entry.root.remove(); // 移除挂载根（view-clear 不负责）
    } catch {
      // 销毁失败不阻塞用例收尾
    }
  }
}
```

`setup.ts` 的 afterEach 调用点同步加 await。
