| -------- | ----------------------------------------------------------------------------------------------------- |
| 优先级   | **P2（中，安全纵深缺失 + 跨端）**                                                                     |
| 风险类别 | 权限/URL 注入（纵深防御缺失）；运行错误（Web 开发态）                                                 |
| 引入提交 | `865c353` feat(editor): 链接 Ctrl+点击系统浏览器打开                                                  |
| 涉及文件 | `src/features/editor/link/open-link.ts:24-27`、`src/services/external-open.ts:12-14`                  |
| 相关测试 | `e14-link.spec.ts`（仅 https 正常路径/空 href/普通点击；**无协议攻击用例**）、`external-open.spec.ts` |

**问题描述**：两处独立缺陷叠加：

1. **无协议白名单**：`open-link.ts` 取 `linkMark.attrs.href` 后原样传给 `openExternalUrl`，
   `external-open.ts` 注释声称"目标 URL（http/https）"但实现 `await openUrl(url)` 原样透传，契约与实现不符。
   当前被 tauri-plugin-opener 2.5.4 的 capability ACL（仅 `mailto:* / tel:* / http://* / https://*`）外部兜底；
   但注释明示"12 窗口外壳模块可用相同签名替换实现"——替换实现绕过 ACL 即直接暴露

   `window.__TAURI_INTERNALS__` 抛 TypeError，调用方 `void openExternalUrl(href)` 无 try/catch
   无 `window.open` 兜底 → unhandled promise rejection，链接不打开。

**代码证据**

```ts
// open-link.ts:24-27
const href = linkMark.attrs.href as string; // 文档内容可控，无任何协议校验
if (!href) return false;
event.preventDefault();
void openExternalUrl(href);
// external-open.ts:12-14（注释承诺 http/https，实现原样透传）
export async function openExternalUrl(url: string): Promise<void> {
  await openUrl(url);
}
```

**修复方向**：`openExternalUrl` 内做协议白名单校验（仅 http/https，可含 mailto/tel），非白名单协议
return 不打开；`open-link.ts` 调用处补 catch 或 Web fallback（`window.open`），并补 e14 协议攻击用例。
