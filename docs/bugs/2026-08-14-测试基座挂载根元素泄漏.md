# 测试基座 makeTestEditor 挂载根元素泄漏（destroy 不 await、不移除 root）

- 日期：2026-08-14
- 风险等级：**中（资源泄漏，测试环境可复现）**
- 风险类别：资源泄漏（DOM 节点泄漏，跨用例累积）
- 引入提交：`a0c8bb5` test(editor): 搭建编辑器测试基座（jsdom stubs + Crepe 测试助手 + 工厂）
- 涉及文件：`src/test/editor-test-utils.ts`（新增，101 行）
- 验证方式：静态分析 + 实验复现（一次性验证脚本，跑完即删，未改动仓库）

## 问题描述

测试助手 `makeTestEditor` 向 `document.body` 追加挂载根 div（见 `editor-test-utils.ts:60-61`），
但收尾清理 `destroyTestEditors`（`editor-test-utils.ts:41-49`）存在两个缺陷：

1. **不 await `crepe.destroy()`**：`Editor.destroy` 为异步流程（`@milkdown/core` 中为 `async`），
   调用后立即返回时内部 DOM 尚未清理（实验显示同步检查时 13 个 div 全部残留）。
2. **不移除 root div 本身**：`@milkdown/core` 的 view-clear 插件销毁时只移除 `.milkdown` 容器
   （`node_modules/@milkdown/core/lib/index.js:480-483`：`container?.remove()`），
   外部传入的 root div 不在其清理范围内——产品路径 `editorManager.destroy()` 显式调用
   `this.root?.remove()`（`src/services/editor-manager.ts:80`）补偿，测试助手缺失该补偿。

## 代码证据

`src/test/editor-test-utils.ts`：

```ts
// 行 41-49：销毁全部存活的测试编辑器（setup.ts 的 afterEach 调用）
export function destroyTestEditors(): void {
  for (const crepe of liveEditors.splice(0)) {
    try {
      crepe.destroy(); // ← ① 不 await：异步清理未完成即返回
    } catch {
      // 销毁失败不阻塞用例收尾
    }
  }
  // ← ② 缺失 root.remove()：挂载根 div 永久残留 document.body
}
```

```ts
// 行 60-61：makeTestEditor 创建挂载根并追加到 body
const root = document.createElement("div");
document.body.appendChild(root);
```

对照（产品路径，`src/services/editor-manager.ts:79-81`，修复过的同一问题）：

```ts
// 移除挂载根元素：@milkdown/core 的 view-clear 只清理编辑器内部容器，root div 须自行移除
this.root?.remove();
this.root = undefined;
```

上游事实（`node_modules/@milkdown/core/lib/index.js:480-483`，view-clear 插件 destroy）：

```js
return {
  destroy: () => {
    if (container?.parentNode) container?.parentNode.replaceChild(editorView.dom, container);
    container?.remove(); // 只移除 .milkdown 容器，root div 不在清理范围
  },

```

## 实验复现（一次性验证脚本）

```
[DBG-B2] before=0 afterCreate=13 afterDestroySync=13 afterMicrotask=1 strayRootDivs=1
```

- `afterDestroySync=13`：destroyTestEditors 同步返回时 13 个 div 全部残留（异步销毁未执行）；
- `afterMicrotask=1`：await 50ms 后内部 12 个 div 已被销毁流程清理，但 **root div 永久残留**（strayRootDivs=1）；
- 同一测试文件内每用一次 `makeTestEditor` 即向 body 累积 1 个 root div。

## 影响

- 测试文件内用例间 DOM 累积，污染依赖 `document.body` 全局查询的断言。
  已受影响示例：`src/services/editor-manager.spec.ts:44-48`「连续 create 两次无重叠」用
  `document.body.querySelectorAll("div").length` 做精确计数——该用例目前因执行顺序恰好未被污染，
  一旦用例顺序调整（如 adopt 用例前置）即产生误报，属脆弱断言。
- 与产品路径行为不一致：产品销毁会移除 root，测试基座不会，掩盖"销毁是否干净"的验证能力。
- 覆盖率/内存层面无直接影响，但为后续大量编辑器用例埋下断言污染隐患。

## 修复建议

`destroyTestEditors` 改为 async 并记录/移除各实例的 root：

```ts
export async function destroyTestEditors(): Promise<void> {
  for (const entry of liveEditors.splice(0)) {
    try {
      await entry.crepe.destroy(); // 等待异步销毁完成
      entry.root.remove(); // 移除挂载根（view-clear 不负责）
    } catch {
      // 销毁失败不阻塞用例收尾
    }
  }
}
```

`makeTestEditor` 需把 `root` 一并登记（`liveEditors` 元素由 `Crepe` 改为 `{ crepe, root }`），
`setup.ts` 的 afterEach 调用点同步加 await。
