# 硬换行规则缺少"光标在行尾"判定，段中两空格后按 Enter 误转硬换行

- 日期：2026-08-14
- 风险等级：**高（行为错误，可复现）**
- 风险类别：运行错误（用户可观察的错误行为）
- 引入提交：`bb30c90` feat(editor): 行尾两空格+Enter 硬换行转换规则（E1-3 回退实现）
- 涉及文件：`src/features/editor/input-rules.ts`（新增，58 行）
- 验证方式：静态分析 + 真实 Crepe 实例实验复现（一次性验证脚本，跑完即删，未改动仓库）

## 问题描述

`trailingSpacesHardBreakCommand`（E1-3 行尾两空格硬换行规则）只检查**光标前紧邻两字符是否为空格**，
**未检查光标后是否仍有内容（是否位于行尾）**。导致用户在段落中间（光标后仍有文本）按 Enter 时
被误判为"行尾硬换行"：段落不拆分、强制插入 hardBreak 节点，与 Typora 及 E1-3 AC 的"行尾"语义不符。

## 代码证据

`src/features/editor/input-rules.ts:31-45`（提交 bb30c90）：

```ts
export function trailingSpacesHardBreakCommand(state: EditorState, dispatch?: Dispatch): boolean {
  const { selection } = state;
  // 仅处理行内文本光标：非文本选区（跨节点选区）不干预
  if (!(selection instanceof TextSelection) || !selection.empty) return false;
  const { $from } = selection;
  // 光标父节点必须是文本块（段落/标题/列表项等）；文档级光标不处理
  if (!$from.parent.isTextblock) return false;
  // 行尾检测：光标前紧邻的两个字符均为空格才转换（CommonMark 硬换行语法）
  const textBefore = $from.parent.textBetween(0, $from.parentOffset);
  if (!textBefore.endsWith("  ")) return false; // ← 仅检查光标前，无行尾（光标后无内容）校验
  if (!dispatch) return true;
  // 在行尾两空格之后插入 hardBreak 节点；光标随插入映射到换行之后
  dispatch(state.tr.insert($from.pos, state.schema.nodes.hardbreak.create()).scrollIntoView());
  return true;
}
```

关键缺口：注释自称"行尾检测"，但判定条件 `textBefore.endsWith("  ")` 只反映"光标前两字符是空格"。
当光标位于段落中间（如 `ab␣␣|cd`，光标后仍有 `cd`）时同样满足条件。
正确实现应额外校验光标位于块尾，例如 `$from.parentOffset === $from.parent.content.size`（光标后无任何内容）。

## 实验复现（真实 Crepe 7.22.1 + jsdom，一次性验证脚本）

场景：空文档直插文本 `ab␣␣cd`，光标置于两空格之后（"cd" 之前），按 Enter：

```
[DBG9] textBefore="ab  c"        ← 首次位置偏差（+2 偏移），未命中（对照）
[DBG9] 行中间 hasHB=false childCount=2   ← 光标在 "c" 与 "d" 之间：未命中，正确拆段
[DBG9] 空格中间 hasHB=true childCount=1 序列化="ab  \\\ncd"  ← 光标在两空格后（"c" 前）：
       命中！段落未拆分（childCount=1），hardBreak 插入段中，序列化出现转义 "\\\n"
```

对照组（正确场景，段尾两空格）：`e1-paragraph.spec.ts` 的 AC-E1-3 精确重现——
光标在段尾时命中并正确插入 hardBreak（`hasHB=true, childCount=1, 序列化="行一  \n"`），此路径无问题。

## 影响

- 用户输入 `文本␣␣` 后（中间任意位置）按 Enter 期望拆分段落，实际得到**段内硬换行**（段落不拆）。
- 与 Typora 行为不一致（Typora 仅"行尾"两空格+Enter 才转硬换行）。
- 序列化输出为 `␣␣\\\n`（remark 对段中 hardBreak 的转义）或 `␣␣ \n`，落盘语法歧义。
- 该 keymap 以 priority 200 消费 Enter，命中即阻断内置 splitBlock，用户无法通过其他途径拆段（只能先移动光标）。

## 测试缺口

`input-rules.spec.ts`（bb30c90）5 个用例全部聚焦"行尾/未命中"分支，**缺少"光标前两空格但光标后仍有内容"的
负例用例**；`vite.config.ts` 对 `src/features/editor/**/*.ts` 配置了 100% branches 阈值，
但该未覆盖分支未触发阈值失败（说明当前分支统计口径未覆盖此场景或阈值未执行）。

## 修复建议

命中前增加行尾校验（二选一即可）：

```ts
// 行尾校验：光标之后到块尾无任何内容才视为"行尾"
if ($from.parentOffset !== $from.parent.content.size) return false;
```

同步补一条负例用例：`ab␣␣cd` 光标在两空格后按 Enter → 断言段落拆分（childCount=2）且无 hardBreak。
