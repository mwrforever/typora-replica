## 2. 已回帖问题（score ≥ 80）

### A【100｜数据完整性】自动保存 5 分钟定时兜底无条件写盘，干净文档被静默改写

- **位置**：`src/services/auto-save.ts:62-70`（saveIfPossible）、`73-82`（refreshTimer）；`src/services/document-session.ts:129-147`（save）
- **问题**：`start()` 无条件挂 5 分钟定时器；到期 `saveIfPossible` 仅检查 stopped 与 `autoSave.enabled`，无条件 `session.save()`，整条链路从不检查 `session.dirty`。打开文档后不做任何编辑，5 分钟后必然被重写一次：`getMarkdown()` 剥掉全部尾随换行 → `toDiskContent()` 补单尾换行 + 按默认行尾归一 → UTF-8 无 BOM 落盘。后果：无尾换行文件被追加 `\n`、多个尾随空行被折叠、CRLF 文件整文件转 LF（Git 整文件 diff）、GBK 文件被静默重编码为 UTF-8、只读位置的文件每 5 分钟弹一次写盘失败。
- **依据**：spec AC-F30-1/2 的触发条件均为编辑场景（停笔/持续编辑）；自动保存默认开启（`settings.ts:42`），使用会话内每 5 分钟触发一次；`auto-save.spec.ts` 无"未编辑定时到期不写盘"用例（反向证实缺陷未被察觉）。
- **建议修复**：`saveIfPossible` 前置 `session.dirty` 检查（或 `save()` 内部干净短路）；补"干净文档定时到期不写盘"测试用例。
- **状态**：已回帖 PR（comment 5305394329）；**已修复 2026-08-16**——`saveIfPossible` 前置 dirty 检查（手动 Ctrl+S 走 `session.save()` 不受影响）；补「干净文档定时到期不写盘」用例。
