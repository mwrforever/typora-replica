## 1. 模块定位与边界

**做什么**：多标签页体系——标签条 UI、每标签一个编辑器实例的生命周期管理、标签切换/关闭/重开、关闭脏标签确认。**官方 Windows 无标签页（Not Supported），本模块是差异化卖点功能，行为规范自定（对齐业界惯例）**。

**不做什么**：

- 窗口级菜单装配与快捷键注册（12 窗口外壳，04 只暴露 store action 供菜单调用）
- New Window 多窗口（12）
- 跨窗口标签状态同步（首版不做，各窗口独立）
- 编辑器内核（01）

## 2. 功能点细化（验收标准驱动）

### F29 标签页

- 架构：**每标签一个 Crepe 实例 + v-show 保活**；保活上限 16 + LRU 回收（超限销毁最久未激活实例，内容以 markdown 字符串留 contentSnapshot，重激活重建）；编辑器实例存模块级 Map 注册表（不进 Pinia）
- 标签条：新建（未命名 Untitled N）/切换/关闭（×）/右键菜单；关闭当前标签后激活右侧相邻（无右侧则左侧）；Ctrl+Tab 正向轮换、Ctrl+Shift+Tab 反向
- Ctrl+Shift+T：LIFO 重开最近关闭（**恢复脏快照**，用户拍板）；重开栈深度 20（自定）；默认不跨会话
- 脏状态：由 02 自动保存链路驱动（markdownUpdated → dirty=true；写盘成功 → dirty=false）

| 编号     | 类型 | 验收标准                                                                                                      |
| -------- | ---- | ------------------------------------------------------------------------------------------------------------- |
| AC-F29-1 | 正常 | Given 按 Ctrl+N，Then 新建未命名标签并激活（标题 Untitled N 递增）                                            |
| AC-F29-2 | 正常 | Given 从文件树打开文件，Then 新增标签；已打开的文件去重激活既有标签                                           |
| AC-F29-3 | 正常 | Given 多个标签，When 按 Ctrl+Tab，Then 按标签条顺序正向轮换；Ctrl+Shift+Tab 反向                              |
| AC-F29-4 | 边界 | Given 关闭当前标签，Then 激活右侧相邻标签；无右侧时激活左侧                                                   |
| AC-F29-5 | 正常 | Given 关闭一个标签，When 按 Ctrl+Shift+T，Then 重开该标签且恢复关闭前的未保存内容（脏快照）                   |
| AC-F29-6 | 边界 | Given 连续关闭 25 个标签，Then 重开栈只保留最近 20 个                                                         |
| AC-F29-7 | 边界 | Given 打开超过 16 个标签并切换激活，Then 最久未激活标签的编辑器实例被回收（内存受限），重新激活时内容正确重建 |
| AC-F29-8 | 正常 | Given 切换标签，Then 各标签光标位置/撤销历史相互独立不串台                                                    |
| AC-F29-9 | 异常 | Given 关闭最后一个标签，Then 应用不崩溃（空态或新建文档）                                                     |

### C2 未保存提示（标签关闭确认）

- 行为：关闭脏标签弹「保存/不保存/取消」三按钮；「保存」走 02 保存链路成功后关闭；「不保存」丢弃变更关闭（重开栈快照取磁盘版本）；「取消」中止；无脏变更不弹窗

| 编号    | 类型 | 验收标准                                                 |
| ------- | ---- | -------------------------------------------------------- |
| AC-C2-1 | 正常 | Given 脏标签按 Ctrl+W，Then 弹出「保存/不保存/取消」确认 |
| AC-C2-2 | 正常 | Given 确认弹窗选「保存」，Then 写盘成功后标签关闭        |
| AC-C2-3 | 边界 | Given 确认弹窗选「取消」，Then 标签保持打开且内容不变    |
| AC-C2-4 | 边界 | Given 干净标签按 Ctrl+W，Then 直接关闭不弹窗             |
| AC-C2-5 | 正常 | Given 未命名脏标签选「保存」，Then 转为另存为流程        |

## 3. 非功能要求

- **性能（C5）**：标签切换零重建（v-show 保活）；后台标签的代码块依赖 Crepe 离屏懒回收；内存受 16 上限约束
- **一致性**：脏状态是 02/04/12 三模块共享语义，用单一事件源（02 写盘事件）驱动

## 4. 测试策略

- **前端 Vitest**（核心功能 100%）：tabsStore 全部 action（打开去重/关闭邻位/LIFO 重开/LRU 回收顺序/脏状态流转）——标签簿记是核心状态机
- **组件测试**：标签条渲染、确认弹窗三按钮分支
- **E2E**：多标签开关与切换、脏确认弹窗（本地 CDP/WebDriver）
- **CI**：Vitest 全绿；内存回收行为在 E2E 长场景验证

## 5. 依赖与接口

- **消费**：
  - 01：编辑器实例 create/destroy/getMarkdown（每标签一实例）
  - 02：打开/保存命令、写盘成功事件（dirty=false）
- **提供**：
  - `useTabsStore`（Pinia 单例）：tabs/activeTabId/closedStack + actions（openFile/createUntitled/closeTab/activate/activateNeighbor/reopenClosed/closeAll）
  - `editorRegistry`（模块级 Map<tabId, EditorHandle>）：注册/注销/保活回收
  - 聚合脏状态（供 12 退出应用时列表式确认）
- **前端↔Rust 边界**：纯前端模块，无直接 Rust 接触
