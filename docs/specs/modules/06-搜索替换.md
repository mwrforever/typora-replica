## 1. 模块定位与边界

**做什么**：当前文件查找/替换面板（Find 与 Find+Replace 两个面板态）、正则捕获组替换、跨文件全局搜索（Rust 扫描 + 结果列表 + 点击打开定位高亮）。

**不做什么**：

- 全局搜索入口的侧栏装配（03 的 F12 入口，12 的菜单注册）
- 跨文件替换（官方无记载，推断不支持 → 首版不做）
- searchService 右键第三方搜索（10 设置模块）
- 打开标签与脏状态管理（04）

## 2. 功能点细化（验收标准驱动）

### F24 当前文件查找

- 行为：Ctrl+F 开关 Find 面板、Ctrl+H 开关 Find+Replace 面板；**查找从当前光标位置开始**；Find 命令不改变现有选区；匹配计数显示（3/10，用户实测）；输入实时高亮全部匹配；面板记忆上次关键词；ESC 关闭面板焦点回编辑器；面板关闭后 F3 不再继续；F3/Enter 下一个、Shift+F3/Shift+Enter 上一个
- 实现：官方 prosemirror-search 1.1.1 模块 + 自研面板 UI

| 编号     | 类型 | 验收标准                                                     |
| -------- | ---- | ------------------------------------------------------------ |
| AC-F24-1 | 正常 | Given 按 Ctrl+F，Then 打开 Find 面板并聚焦输入框             |
| AC-F24-2 | 正常 | Given 输入关键词，Then 实时高亮全部匹配并显示计数（如 3/10） |
| AC-F24-3 | 边界 | Given 查找从光标位置开始（光标在文档中部时先命中中部匹配）   |
| AC-F24-4 | 正常 | Given 按 F3，Then 跳转下一个匹配；Shift+F3 上一个            |
| AC-F24-5 | 边界 | Given 按 ESC，Then 关闭面板且焦点回到编辑器                  |
| AC-F24-6 | 异常 | Given 输入无匹配关键词，Then 计数 0/0 且不崩溃               |

### F25 正则替换

- 行为：Ctrl+H 打开 Find+Replace 面板；大小写/全词/正则三开关；**Replace All「全部」按钮**（用户实测）；替换串支持 `$0`/`$1`/`$2` 捕获组；替换走原生 replaceStep 自动进 undo（单次一个 undo 步、replaceAll 一次全撤）；非法正则安全拒绝（query.valid=false）

| 编号     | 类型 | 验收标准                                                             |
| -------- | ---- | -------------------------------------------------------------------- |
| AC-F25-1 | 正常 | Given 按 Ctrl+H，Then 打开 Find+Replace 面板                         |
| AC-F25-2 | 正常 | Given 正则模式查找 `(\w+)@(\w+)` 替换为 `$2@$1`，Then 捕获组正确交换 |
| AC-F25-3 | 正常 | Given 点击「全部」按钮，Then 全部匹配被替换且一次 Ctrl+Z 全部撤销    |
| AC-F25-4 | 正常 | Given 逐个替换，Then 每次替换后选中下一匹配                          |
| AC-F25-5 | 异常 | Given 输入非法正则（如 `(`），Then 安全拒绝不崩溃                    |
| AC-F25-6 | 边界 | Given 开启全词匹配搜索 `cat`，Then `concatenate` 不命中              |

### F26 跨文件搜索

- 行为：入口（03 F12 联动）打开全局搜索；大小写/全词/正则三开关；结果条 = 文件名 + 行号 + 匹配行上下文（用户实测）；同文件多匹配默认折叠可展开；**结果上限约 50 行截断**（用户实测）；点击结果 → 激活/新开标签 → 光标选中匹配并滚动 + 临时高亮 3 秒（用户拍板）；跳过隐藏文件与二进制；无跨文件替换
- 实现：Rust `search_in_folder`（ignore 并行遍历 + regex 行扫描 + encoding_rs_io 转码 + 流式结果 + 取消）

| 编号     | 类型 | 验收标准                                                                   |
| -------- | ---- | -------------------------------------------------------------------------- |
| AC-F26-1 | 正常 | Given 输入搜索词，Then 列出当前文件夹所有匹配文件（文件名+行号+上下文行）  |
| AC-F26-2 | 正常 | Given 点击结果条目，Then 打开/激活对应标签并光标选中匹配文本、滚动到可视区 |
| AC-F26-3 | 边界 | Given 结果超上限，Then 截断显示约 50 行并提示截断                          |
| AC-F26-4 | 边界 | Given 开启大小写敏感，Then 只命中大小写一致的匹配                          |
| AC-F26-5 | 异常 | Given 目录含 GBK 文件，Then 经转码正确搜索且结果标注非 UTF-8               |
| AC-F26-6 | 正常 | Given 搜索进行中再输入新词，Then 前次搜索取消（取消标志）                  |

## 3. 非功能要求

- **性能（C5）**：regex 线性时间（无灾难性回溯）；大目录并行遍历 + 流式返回不阻塞 UI；大文档查找防挂起（prosemirror-search 官方保障）
- **一致性**：查找高亮样式独立于 `==高亮==` 语法（官方 1.4）；暗色主题下高对比（08 主题适配点）

## 4. 测试策略

- **前端 Vitest**（核心 100%）：面板状态机（开关/计数/选区语义）、$n 替换（含非捕获组）、全词/大小写开关、面板生命周期
- **Rust 单测**（核心 100%）：search_in_folder（正则/全词/大小写/GBK 转码/隐藏与二进制跳过/结果上限/取消）
- **E2E**：Ctrl+F/Ctrl+H 面板、跨文件搜索→点击定位链路（本地 CDP/WebDriver）
- **CI**：cargo test + Vitest 全绿

## 5. 依赖与接口

- **消费**：
  - 01：编辑器实例 + **新增 revealRange(from, to)**（选中 + 滚动 + 临时高亮 3 秒）
  - 02：read_file（编码探测）、编码转码 helper
  - 04：useTabsStore.openFile（去重激活）
  - 03：F12 入口事件（request-search）
- **提供**：
  - `searchPanelStore`（Pinia）：Find/Replace 面板状态
  - Rust command：`search_in_folder(root, query, {caseSensitive, wholeWord, regexp, maxResults}) -> 流式事件`
- **前端↔Rust 边界**：跨文件扫描在 Rust（ignore+regex），结果流式推送 + 取消
