## 1. 模块定位与边界

**做什么**：WYSIWYG 编辑器本体——Milkdown Crepe 的挂载、21 个语法功能点的行为实现、快捷键体系（keymap 注册）、编辑器实例与内容变更事件对外的接口。

**不做什么**：

- 文件读写/自动保存/草稿恢复（02 文档管理）
- 图片存盘与路径策略（07 图片粘贴存盘，本模块只提供 onUpload 接口）
- 主题系统与主题 CSS 变量覆盖层（08 主题）
- 菜单栏/侧边栏等窗口装配（12 窗口外壳）
- E13 Callouts（首版不做，需启用项非核心）
- E17 Emoji 补全菜单、E18 上标/下标/高亮（延后，后续里程碑）

## 2. 功能点细化（验收标准驱动）

> 验收标准编号 AC-E{功能点}-{序号}，每条可直译为 Vitest 用例或 E2E 场景。
> 行为依据：Typora 官方文档 + 用户实操校准（2026-08-13），见调研文档。

### E1 段落与换行（开箱即用）

- 行为：Enter 新建段落（单空行即可）；Shift+Enter 软换行；行尾两空格与 `<br/>` 为硬换行兼容语法；源码模式落盘为两个换行符
- 边界：软换行/连续空格默认「编辑视图保留、打印/导出忽略」（设置项位于偏好设置→Markdown 分区，属 10 设置快捷键模块）

| 编号    | 类型 | 验收标准                                                                   |
| ------- | ---- | -------------------------------------------------------------------------- |
| AC-E1-1 | 正常 | Given 文档含一段文本，When 在段中按 Enter，Then 拆分为两个段落             |
| AC-E1-2 | 正常 | Given 光标在段落内，When 按 Shift+Enter，Then 产生硬换行（hardBreak 节点） |
| AC-E1-3 | 边界 | Given 行尾输入两个空格，When 换行，Then 落盘为兼容性硬换行（渲染为换行）   |
| AC-E1-4 | 异常 | Given 文首空文档，When 连续按 Enter 5 次，Then 文档状态不报错、段落数正确  |

### E2 标题（轻）

- 行为：行首 1-6 个 `#` + Enter 转标题；**默认非严格模式 `#` 后不强制空格**（`###Header` 亦转标题）；Ctrl+1~6 设级别；Ctrl+0 转段落；Ctrl+=/- 增减级别
- 边界：H1 再升级保持 H1；H6 再降级保持 H6

| 编号    | 类型 | 验收标准                                                                              |
| ------- | ---- | ------------------------------------------------------------------------------------- |
| AC-E2-1 | 正常 | Given 行首输入 `# ` + 标题文字，When 按 Enter，Then 该行渲染为 H1                     |
| AC-E2-2 | 边界 | Given 行首输入 `###Header`（无空格），When 按 Enter，Then 渲染为 H3（非严格模式宽容） |
| AC-E2-3 | 正常 | Given 选中一段文本，When 按 Ctrl+2，Then 该文本成为 H2 标题                           |
| AC-E2-4 | 边界 | Given H3 标题光标在行内，When 按 Ctrl+=，Then 升级为 H2；再按 Ctrl+- 降回 H3          |
| AC-E2-5 | 异常 | Given H1 标题，When 按 Ctrl+=，Then 保持 H1 不变（无越界级别）                        |
| AC-E2-6 | 正常 | Given 任意标题，When 按 Ctrl+0，Then 转为普通段落                                     |

### E7 数学块（轻）

## 3. 非功能要求

- **性能（C5）**：万行级文档编辑流畅；大量代码块场景依赖 Crepe 懒初始化（IntersectionObserver + 离屏 teardown）已验证存在，压测场景为「万行文本 + 百个代码块/表格/图片混合」；getMarkdown 全量序列化 O(n)，对外事件必须防抖
- **编码（C3）**：文档内容 UTF-8；由 02 文档管理负责编码探测，本模块只处理字符串
- **安全（C4）**：DOMPurify 白名单清洗（E20）；script 禁用、iframe sandbox（安全路径，100% 单测覆盖）
- **主题可覆盖性**：Crepe 主题 CSS 变量体系允许上层覆盖（08 主题在 Crepe 主题 CSS 之上追加变量覆盖层，T6 base.user.css 落此层）

## 4. 测试策略

- **单元测试（Vitest）**：全部 AC 编号直译为用例；核心功能（用户输入→文档状态变更的语法转换、安全路径 E20）**100% 覆盖**；非核心（语言列表映射等）≥80%
  - 测试工具：@milkdown/vue 官方测试模式（crepe.test.tsx 样例）+ @testing-library
- **E2E（本地 CDP/WebDriver，e2e/）**：编辑器挂载、语法输入规则、快捷键注册三个冒烟场景
- **CI**：Quality Gate 跑 Vitest 全量；CI 冒烟为确定性验证（不依赖 CDP 调试端口，见 e2e/README.md）

## 5. 依赖与接口

- **上游依赖**：无
- **对外接口（本模块暴露，供其他模块消费）**：
  - 编辑器实例管理：create/destroy/getMarkdown/setReadonly/useInstance
  - 内容变更事件：markdownUpdated（防抖后对外）→ 02 自动保存、05 大纲、11 字数统计、12 标题栏脏状态
  - 图片上传回调：onUpload(file): Promise<string> → 07 图片模块注入实现
  - keymap 注册表 → 10 设置快捷键模块可扩展
- **前端↔Rust 边界**：本模块纯前端；E14 浏览器打开经 opener 插件调用 Tauri 能力（由 12 窗口外壳统一暴露）
